# Product docs

Industry-standard split: **why/what** vs **how it behaves**.

| #   | Document                                                     | Standard name            | Read when                                            |
| --- | ------------------------------------------------------------ | ------------------------ | ---------------------------------------------------- |
| 01  | [**01-PRODUCT-OVERVIEW.md**](01-PRODUCT-OVERVIEW.md)         | Product Overview / Brief | First — ~5 min, whole product                        |
| 02  | [**02-ROADMAP.md**](02-ROADMAP.md)                           | Roadmap                  | Build order — M1 → M4, no deadlines                  |
| 03  | [**03-PRODUCT-REQUIREMENTS.md**](03-PRODUCT-REQUIREMENTS.md) | PRD / Functional spec    | Building, designing, or testing a feature            |
| 04  | [04-OOUX-OBJECT-MAP.md](04-OOUX-OBJECT-MAP.md)               | Concept model            | Dog profile structure — SVG diagrams + `.mmd` source |
| 05  | [Z-DISCOVERY.md](Z-DISCOVERY.md)                             | Discovery worksheet      | Tracing where a requirement came from                |

**Reading order:** 01 → 02 → 03 → 04 (when building M1) → Z-DISCOVERY (only to trace a decision)

**Authoring order** (how these were produced): Z-DISCOVERY → 01 → 03 → 04 → 02

**Legacy docs** (Phase 1–5, Eleventy-centric): [`../archive/`](../archive/README.md) — archived, do not use for new work.
